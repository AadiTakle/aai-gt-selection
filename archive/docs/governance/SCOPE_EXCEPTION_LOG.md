# Scope Exception Log

## Purpose

This log makes deliberate boundary crossings visible. It does not normalize scope creep.

A scope exception is required when proposed work:

- cannot map to an existing R/H requirement;
- conflicts with a project non-goal;
- adds a new stakeholder, outcome, system, or research question;
- consumes material effort that displaces required work; or
- needs a temporary deviation from an approved requirement or rubric gate.

## Approval process

1. Submit the exception before implementation.
2. Explain why existing requirements cannot cover the work.
3. Identify displaced work, cost, risk, and expiration.
4. Obtain team-lead approval and any affected domain-owner approval.
5. Add a decision-log entry if the exception changes enduring scope.
6. Review or close the exception on its expiration date.

Emergency action may occur first only to protect people, data, or irreversible project assets. Document it immediately afterward.

## Exception template

### X-XXX — Exception title

- **Requested:** YYYY-MM-DD
- **Status:** Proposed / Approved / Expired / Closed / Rejected
- **Requester:** Name
- **Work proposed:** Specific deliverable
- **Boundary crossed:** Charter, requirement, rubric gate, or non-goal
- **Why required:** Why in-scope alternatives are insufficient
- **Benefit:** Expected contribution
- **Cost and displaced work:** Time, complexity, or required work delayed
- **Risks:** Validity, applicant, operational, privacy, or delivery risks
- **Acceptance evidence:** How the exception's value will be evaluated
- **Approvers:** Team lead and affected owners
- **Expiration/review date:** Date or milestone
- **Closure condition:** What ends the exception
- **Related decision:** Decision-log ID, if scope changes permanently

## Enforcement

- An approved exception authorizes only the named work and duration.
- Exceptions cannot waive student protection, evidence honesty, or claim-boundary requirements.
- Expired exceptions revert to the canonical scope automatically.
- Repeated exceptions for the same work indicate that the charter or requirements need formal revision.
